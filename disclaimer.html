Tool-specific limitations

  • JSON and code formatting: syntactic validity does not establish that a payload matches your schema, behaves correctly, or is safe. Minification and formatting can alter whitespace; test the resulting artifact with your actual parser and application.
  • Base64: encoding is reversible representation, not encryption, authentication, integrity protection, or access control. Never put secrets in Base64 under the assumption that they are hidden.
  • URL encoding: the correct escaping depends on whether a value is a component or a complete URL. Percent-encoding is not a universal sanitizer for HTML, SQL, shell, JavaScript, or HTTP headers.
  • UUIDs: collision probability depends on version and randomness source. UUIDs are not guaranteed globally unique in a mathematical sense and are not a replacement for authorization tokens or server-side access checks.
  • File data URIs: inline data increases document size and can complicate caching and content security policies. Review file content and size before embedding it.
